# P1-observability: Correlated Audit Logs Across MCP, Signer, and Tx Execution

## Summary

Implement a unified audit logging system that correlates events across the MCP layer, the signer component, and transaction execution into traceable audit trails.

## Context

In a managed-backend deployment, operators need full visibility into who did what, when, and with what result. Currently, MCP events, signing operations, and on-chain tx execution produce isolated logs with no correlation. This makes incident response and compliance auditing impossible.

## Requirements

- [ ] **Correlation ID**: Every request gets a `correlation_id` (ULID) propagated across all layers
- [ ] **MCP layer events**: Request receipt, auth result, rate limit action, tool dispatch
- [ ] **Signer events**: Signing request, signature produced, key ID used
- [ ] **Tx execution events**: Tx submission, hash received, confirmation status
- [ ] **Structured format**: JSON logs with standardized schema
- [ ] **Log aggregation**: Centralized log store (e.g., Loki, Elasticsearch, or cloud-native equivalent)
- [ ] **Retention policy**: Configurable retention (default: 90 days)
- [ ] **Query API**: REST endpoint to retrieve audit trail by correlation ID

## Log Schema

```yaml
audit_log:
  correlation_id: ulid          # unique trace identifier
  timestamp: iso8601            # event time
  layer: mcp | signer | tx      # source layer
  event_type: string            # specific event
  session_key: string           # originating session
  tool_name: string | null      # tool involved (MCP)
  key_id: string | null         # signing key (signer)
  tx_hash: string | null        # on-chain tx hash
  result: success | failure     # outcome
  metadata: object              # additional context
  severity: info | warn | error | critical
```

## Testing

- Unit: ULID generation and parsing
- Unit: log schema validation
- Integration: end-to-end correlation ID propagation
- Integration: log query API
- Load: log volume under high throughput (10k events/sec)

## Runbook

1. Retrieve audit trail: query `/audit/trail/{correlation_id}`
2. Investigate incident: filter logs by `severity=critical` and time range
3. Compliance export: export logs for retention period via admin API
