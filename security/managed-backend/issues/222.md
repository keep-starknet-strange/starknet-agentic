# P1-mcp: Enforce per-session-key + per-tool rate limiting

## Summary

Implement granular rate limiting at the MCP layer: one limit per session key and one limit per tool invocation, backed by a sliding-window counter.

## Context

Without per-session and per-tool rate limits, a compromised or misbehaving client can flood the system, causing denial of service or excessive chain interaction costs. The no-backend launch does not require this, but managed-backend deployments must enforce it.

## Requirements

- [ ] **Per-session-key limit**: Configurable max requests per session key per time window (default: 60 req/min)
- [ ] **Per-tool limit**: Configurable max invocations per tool per time window (default: 30 req/min)
- [ ] **Sliding window**: Use Redis sorted sets for accurate sliding-window rate counting
- [ ] **Headers**: Return `Retry-After` and `X-RateLimit-Remaining` / `X-RateLimit-Reset` on 429
- [ ] **Burst allowance**: Optional burst capacity (e.g., 2× limit for short bursts)
- [ ] **Override mechanism**: Admin API to temporarily lift limits for specific session keys (logged)

## Data Model

```yaml
# Redis keys
rate:session:{session_key}:{minute_bucket}  → SET of request timestamps
rate:tool:{tool_name}:{minute_bucket}       → SET of request timestamps
```

## API Contract

```yaml
# Rate limit headers on every response
X-RateLimit-Limit: int
X-RateLimit-Remaining: int
X-RateLimit-Reset: int64   # unix epoch seconds

# Rate limit exceeded
429 Too Many Requests: {
  "error": "rate_limit_exceeded",
  "limit": int,
  "remaining": 0,
  "reset_at": int64,
  "scope": "session" | "tool",
  "key": string
}
```

## Testing

- Unit: sliding window counter correctness
- Integration: per-session limit enforcement
- Integration: per-tool limit enforcement
- Integration: burst behavior
- Integration: override mechanism audit logging

## Runbook

1. Tuning limits: adjust defaults in config, deploy, monitor `rate.limit.exceeded` metric
2. Emergency lift: call admin override endpoint, log action with operator ID
3. Redis recovery: counters reset on Redis restart — document cooldown period
