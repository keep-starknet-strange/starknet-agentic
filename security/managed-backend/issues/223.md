# P1-mcp: Add I/O Secret Leak Scanner (Starknet Patterns)

## Summary

Deploy an I/O interception layer that scans request and response payloads for leaked secrets matching known Starknet patterns (private keys, mnemonics, signing keys, etc.).

## Context

Agents interacting with Starknet may accidentally echo back private keys, seed phrases, or signing material in logs, responses, or tool outputs. A scanner at the I/O boundary prevents exfiltration before it leaves the managed backend.

## Known Starknet Secret Patterns

| Pattern | Regex | Severity |
|---------|-------|----------|
| Starknet private key | `0x[a-fA-F0-9]{63,66}` (64-66 hex chars after 0x) | CRITICAL |
| Mnemonic phrase | `\b[a-z]+\s+[a-z]+\s+[a-z]+\s+[a-z]+\s+[a-z]+\s+[a-z]+\s+[a-z]+\s+[a-z]+\s+[a-z]+\s+[a-z]+\s+[a-z]+\s+[a-z]+` (12/24 word BIP39) | CRITICAL |
| ECDSA signature (r, s) | `0x[a-fA-F0-9]{64},\s*0x[a-fA-F0-9]{64}` | HIGH |
| Cairo felt252 private key | `^[0-9]{50,70}$` | HIGH |
| API key (Starknet RPC) | `(?i)(starknet.*(?:key|token|secret))\s*[:=]\s*\S+` | MEDIUM |

## Requirements

- [ ] **Request scanner**: Inspect inbound request bodies and headers
- [ ] **Response scanner**: Inspect outbound response bodies
- [ ] **Tool output scanner**: Intercept tool execution stdout/stderr
- [ ] **Masking**: Replace matched secrets with `[REDACTED:<type>]` in place
- [ ] **Alerting**: Emit structured alert on each detection with context (source, pattern, timestamp)
- [ ] **Configurable rules**: Allow operators to add custom patterns via config
- [ ] **Performance**: Scanner must add <5ms latency per request

## Testing

- Unit: pattern matching against known good/bad inputs
- Unit: masking correctness
- Integration: end-to-end leak detection pipeline
- Performance: latency benchmark (<5ms overhead)
- Fuzz: random payload injection

## Runbook

1. Add custom pattern: update `security/managed-backend/scanner/rules.yaml`, reload scanner
2. Investigate alert: query alert store by pattern type and timestamp
3. False positive tuning: adjust regex specificity in rules config
