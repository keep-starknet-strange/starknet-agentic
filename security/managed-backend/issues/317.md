# P1-mcp-auth: OAuth 2.1 / OIDC Short-Lived Scoped Tokens for MCP Boundary

## Summary

Replace static API keys with OAuth 2.1 / OIDC-compliant short-lived scoped access tokens at the MCP boundary, enabling fine-grained authorization and automatic token expiration.

## Context

The current auth model (or lack thereof in no-backend mode) relies on long-lived credentials. For managed-backend deployments, OAuth 2.1 provides standardized token lifecycle management, scope-based access control, and compatibility with existing identity providers.

## Requirements

- [ ] **Authorization Server**: Integrated or external OIDC-compatible AS
- [ ] **Short-lived tokens**: Access tokens with TTL ≤ 15 minutes; refresh tokens for session continuation
- [ ] **Scoped tokens**: Tokens scoped to specific MCP tools or tool groups
- [ ] **Token introspection**: Validate tokens at the proxy boundary without hitting the core
- [ ] **DPoP (Demonstrating Proof of Possession)**: Optional DPoP binding to prevent token theft
- [ ] **Token revocation**: Support immediate revocation (e.g., on session termination)
- [ ] **Well-known discovery**: Expose `/.well-known/openid-configuration`

## Token Structure

```json
{
  "iss": "https://auth.agent.example.com",
  "sub": "session_sk_abc",
  "aud": "https://mcp.agent.example.com",
  "exp": 1737000000,
  "iat": 1736999100,
  "scope": "mcp:tools:execute:mcp:tools:list",
  "jti": "unique-token-id",
  "token_type": "DPoP"
}
```

## API Contract

```yaml
# Token endpoint
POST /oauth/token
Body: {
  "grant_type": "client_credentials",
  "client_id": "string",
  "client_secret": "string",
  "scope": "mcp:tools:execute"
}
Response: {
  "access_token": "eyJ...",
  "token_type": "Bearer",
  "expires_in": 900,
  "refresh_token": "eyJ...",
  "scope": "mcp:tools:execute"
}

# Revocation
POST /oauth/revoke
Body: { "token": "eyJ...", "token_type_hint": "access_token" }
Response: 200 OK

# Discovery
GET /.well-known/openid-configuration
Response: { "issuer": "...", "authorization_endpoint": "...", ... }
```

## Runbook

1. Configure OIDC provider: set issuer URL, client IDs, and scopes
2. Rotate client secrets: update in secret manager, notify affected clients
3. Handle token theft: invoke revocation endpoint immediately
4. DPoP key rotation: regenerate DPoP key pair, redistribute to clients
